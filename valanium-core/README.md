# valanium-core

Граница доверия клиента. Всё выше этой библиотеки — UI, ему можно отдавать открытый текст. Всё ниже — враждебная среда: сервер, Cloudflare, сеть.

Архитектура — в [../ARCHITECTURE.md](../ARCHITECTURE.md).

Переписка шифруется end-to-end через MLS (RFC 9420, OpenMLS). Сервер видит только шифротекст — это проверяется сквозным тестом, который читает очередь сервера прямо из его базы.

> Интерфейса пока нет ни на одной платформе, и контакты никто не сверяет вручную. До того как
> в UI появится сверка отпечатков, сервер способен на MITM при первом контакте.

## Сборка

```bash
cargo test
```

По умолчанию собирается **инвайт-онли**: команды `request_invoice` и событий `invoice` /
`invoice_paid` в сборке нет, ветка PAY_INFO не компилируется. Код платного входа цел и
возвращается одним флагом:

```bash
cargo test --features ton
```

Сквозная проверка против настоящего сервера на Node — она поднимает его сама:

```bash
cargo test --test cross_language -- --nocapture
```

Юнит-тесты обеих сторон могут быть согласованно неправы: доменный префикс подписи, порядок полей, раскладка кадра. Ловится это только здесь.

## Что внутри

```
src/
  keys.rs     Ed25519: личность, устройство, сертификат, отпечаток
  mls.rs      MLS через OpenMLS: группы, шифрование, привязка листа к устройству
  crypto.rs   Argon2id + XChaCha20-Poly1305, запечатывание записей
  store.rs    SQLite, где содержательное лежит только запечатанным
  proto.rs    кадры — зеркало valanium-server/src/proto/frames.ts
  command.rs  словарь команд и событий, единый для Java и WebView
  client.rs   движок: одно соединение, один цикл, heartbeat, реконнект
  ffi.rs      пять C-функций
```

## Граница FFI

```c
Handle* obs_init(const char* db_path, const char* password);
int     obs_send(Handle*, const char* command_json);
uint8_t* obs_poll(Handle*, uint32_t timeout_ms, size_t* len);   // NULL, если ничего не пришло
void    obs_free(uint8_t*, size_t);
void    obs_shutdown(Handle*);
```

Новая кнопка в интерфейсе — это новый вариант в `Command`, а не новая C-функция. Богатый API пришлось бы биндить дважды, для JNI и для Tauri.

**События забираются опросом, а не колбэком.** Колбэк из чужого потока в JVM требует `AttachCurrentThread` и `GlobalRef` и легко даёт UB при ошибке. Один фоновый Java-поток, крутящий `obs_poll(500)`, не требует ничего.

```java
long h = Core.init(dbPath, password);
new Thread(() -> { for (;;) { String e = Core.poll(h, 500); if (e != null) onEvent(e); } }).start();
Core.send(h, "{\"type\":\"connect\",\"url\":\"wss://valanium.example/ws\"}");
```

## Команды

| Команда | Что делает |
|---|---|
| `register` | создаёт личность и входит по инвайту |
| `request_invoice` | выставляет счёт в TON — **только с `--features ton`** |
| `connect` | вход уже существующей личностью |
| `send` | отправка конверта устройству получателя |
| `history` | локальная история беседы |
| `fingerprint` | отпечаток своей личности |
| `verify` | коды для сверки беседы с собеседником; работает и без подключения |
| `disconnect` | закрыть соединение |

События: `connected`, `registered`, `authenticated`, `conversation_started`, `accepted`, `message`, `queue_done`, `history`, `fingerprint`, `verification`, `anomaly`, `disconnected`, `failed`.

### Сверка и аномалии

`verify` возвращает два числа: `safety_number` (от пары ключей устройств, держится пока ключи те же) и `epoch_code` (от секрета текущей эпохи MLS, меняется на каждом коммите). У исправной беседы оба совпадают у обеих сторон — это проверяется сквозным тестом на двух живых клиентах.

`anomaly` — отдельное событие, а не разновидность `failed`: «не получилось» и «похоже на атаку» интерфейс обязан различать. Приходит, когда в диалоге один на один оказалось не два участника, когда устройство собеседника в беседе не то, что было, и когда отправка заблокирована из-за несовпадения состава.

### Как заводится диалог

`send` на незнакомое устройство не отправляет сообщение сразу: ядро запрашивает у сервера KeyPackage получателя, заводит MLS-группу, шлёт приглашение и только потом — само сообщение. Для UI это невидимо, он получит два `accepted` вместо одного. У получателя появится `conversation_started`, а затем `message`.

`conversation` в событиях — это идентификатор MLS-группы; он же передаётся в `history`.

С `--features ton` добавляются `invoice` и `invoice_paid`.

Поле `payment_ref` у `register` в сборке по умолчанию остаётся в структуре, но получить счёт
нечем, поэтому оно всегда пустое — его можно просто не присылать.

## Что важно знать, если правишь код

- **Подписи проверяются строго** (`verify_strict`). Нестрогий режим ZIP-215 принимает точки малого порядка: ключ из нулей с подписью из нулей проходит, а подделать такую подпись может кто угодно. Сервер настроен так же — тесты с одинаковым списком есть на обеих сторонах.
- **Доменные префиксы** `valanium-auth-v1` и `valanium-device-v1` обязаны совпадать с сервером байт в байт.
- **ACK отправляется после попытки разбора, даже если расшифровать не удалось.** Сервер держит конверт до подтверждения, и без ACK нерасшифровываемый кадр приезжал бы заново при каждом подключении; ошибка при этом видна событием `failed`.
- **Снимок MLS сохраняется после каждого изменения.** Пропущенная запись — это потерянная эпоха и нерасшифровываемая переписка после перезапуска.
- **Привязка MLS-листа к устройству проверяется на каждом сообщении**, а не только при вступлении.
- **`encrypt` требует указать адресата** и откажется шифровать, если состав беседы не тот. Это не перестраховка: отправка вслепую в подставленную группу отдала бы открытый текст.
- **Приватные ключи не сериализуются и зануляются** при уничтожении (`ZeroizeOnDrop`).
- **Ошибки не несут содержимого** — только причину.
