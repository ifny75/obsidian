# Точный промт для агента на сервере

Обнови production-сервер Valanium из архива `valanium-server-2026-08-25-2047.zip`.

Обновление добавляет три вещи: значок и цвет профиля, панель владельца сервера и
блокировку доступа по личности. Ломающих изменений нет — старые клиенты продолжают
работать, новых полей они просто не читают.

Если предыдущие обновления (`0152`, пропуска) вы не ставили — не важно, архив
содержит всё целиком.

## Контекст и жёсткие ограничения

- приложение установлено в `/opt/valanium`;
- systemd-сервис называется `valanium`, tunnel-сервис — `valanium-tunnel`;
- Node.js 24 находится в `/opt/node-24/bin/node`, npm рядом с ним;
- сохрани без изменений `/opt/valanium/.env` и весь `/opt/valanium/data/`;
- не изменяй `/var/www/astryx/`, Apache, основной сайт, Cloudflare Tunnel и другие сервисы;
- сервер после обновления обязан слушать **только `127.0.0.1:8787`**;
- не выводи в ответ содержимое `.env`, токены, инвайты, identity/device keys, аватары,
  значения из таблиц `recoveries`, `usernames`, `passes`, `access`, `blocks`;
- не удаляй старую рабочую копию до успешной проверки новой.

**Зависимости не менялись** — `package.json` и `package-lock.json` идентичны установленным.
`npm ci` всё равно выполни, но новых пакетов он ставить не должен; если он собирается
что-то скачивать, останови обновление и сообщи.

## Порядок действий

1. Проверь архив и создай timestamped backup исходников, `.env` и SQLite через штатный
   `src/tools/backup.ts` либо `VACUUM INTO`; не копируй живой `valanium.db` обычным `cp`
   без WAL/SHM.
2. Распакуй архив во временный каталог, проверь наличие `src/index.ts`, `package.json`,
   `package-lock.json`.
3. Останови только `valanium`.
4. Замени в `/opt/valanium` только исходники и package-файлы из архива. Верни сохранённые
   `.env` и `data/` на прежние места.
5. **Допиши в `/opt/valanium/.env` одну строку**:

   ```
   VALANIUM_ADMINS=<ключ личности владельца, 64 hex-символа>
   ```

   Значение спроси у владельца — он берёт его в клиенте: **Мой профиль → Ключ личности**
   (нажатие копирует). Сам ничего не подставляй и в ответ значение не печатай. Если
   строки нет или она пуста, панель не открывается ни у кого — это безопасное поведение
   по умолчанию, а не поломка.
6. В `/opt/valanium` выполни `/opt/node-24/bin/npm ci --ignore-scripts --omit=optional --omit=dev`
   и `chown -R valanium:valanium /opt/valanium`. Для `.env` установи `chmod 600`.
7. Запусти `valanium`, проверь `systemctl is-active valanium`, затем локально
   `curl --fail http://127.0.0.1:8787/v1/health` и снаружи
   `curl --fail https://valanium.com/v1/health`.
8. Убедись через `ss -ltnp`, что порт 8787 не слушает `0.0.0.0`/`::`, а только loopback.
   Убедись, что `valanium-tunnel` остался active.
9. Проверь, что миграция схемы прошла:

   ```
   sqlite3 /opt/valanium/data/valanium.db "PRAGMA table_info(profiles);"
   sqlite3 /opt/valanium/data/valanium.db "SELECT name FROM sqlite_master WHERE name='blocks';"
   ```

   В первом выводе обязаны быть столбцы `emblem` и `color`, во втором — `blocks`.
   Число строк в `profiles` обязано остаться прежним: сравни с backup.
10. Проверь последние 100 строк `journalctl -u valanium` на ошибки SQLite, TypeScript,
    WebSocket и permissions. Не публикуй чувствительные значения из логов.
11. Если любая проверка провалилась, откати исходники и базу из backup, запусти прежнюю
    версию и сообщи точную ошибку.

## Что нового

### Миграция схемы

`profiles` получает два столбца, таблица не пересоздаётся:

```sql
ALTER TABLE profiles ADD COLUMN emblem TEXT;
ALTER TABLE profiles ADD COLUMN color  TEXT;
```

Миграция идемпотентна и выполняется кодом при старте (`#addProfileDecoration`): столбцы
добавляются, только если их ещё нет. `CREATE TABLE IF NOT EXISTS` существующую таблицу
не меняет — поэтому и понадобился отдельный шаг. Сносить `profiles` нельзя ни при каких
обстоятельствах: в ней коды чатов, по которым людей находят.

Появляется таблица блокировок:

```sql
CREATE TABLE IF NOT EXISTS blocks (
  identity   BLOB PRIMARY KEY REFERENCES users(identity) ON DELETE CASCADE,
  created_at INTEGER NOT NULL
) WITHOUT ROWID;
```

В ней **только личность и время**. Ни причины, ни кто заблокировал, ни переписки — ничего
этого здесь нет и добавлять нельзя. Поля, связывающего двух пользователей, в схеме
по-прежнему не появилось.

### Значок и цвет профиля

`PROFILE_SET (0x18)` теперь принимает, кроме аватара, ещё и `{ emblem, color }`.
Значения — короткие слова из **закрытых списков на сервере**:

- `emblem`: none, star, moon, leaf, flame, drop, bolt, heart, anchor, crown, orbit, shield;
- `color`: none, white, blue, violet, green, coral, amber, teal, rose.

Произвольная строка отвергается как плохой кадр. Это не косметическая придирка: поле
видно собеседнику, и свободный текст означал бы, что любой может показать соседу что
угодно рядом со своим именем. Картинку рисует клиент по своему справочнику — сервер
хранит слово.

Кадр со значком не трогает аватар, и наоборот: они приходят разными полями.

`PROFILE (0x19)` и `USERNAME_FOUND (0x25)` теперь отдают `emblem` и `color`.

Приветствие `HELLO` объявляет о поддержке: `features.decor: true`. Это не украшение
протокола, а защита от старого сервера: он разбирает кадр со значком как «смена
аватара», не находит картинку и рвёт соединение как на битом кадре. Клиенты сначала
спрашивают, а потом отправляют — пока признака нет, они просто говорят человеку, что
сервер ещё не обновлён.

### Панель владельца

Три новых опкода, все требуют AUTH:

- `0x2b ADMIN_GET` — попросить счётчики и страницу списка аккаунтов, `{ offset }`;
- `0x2c ADMIN_OK` — ответ `{ counts, online, startedAt }`;
- `0x2d ADMIN_ACTION` — `{ action: "block" | "unblock", reference }`, где `reference` —
  код чата `OBS-…`, адрес устройства или ключ личности.

`AUTH_OK` дополнен полем `admin: true|false`. **Права выдаёт сервер**; клиент сам себе
панель включить не может.

Кто владелец — определяет `VALANIUM_ADMINS` из окружения, а не строка в базе: строку в
базе можно дописать, получив доступ к диску, переменную окружения — нет. Привязка идёт
к **ключу личности, а не к юзернейму**: имя можно освободить и занять заново, и привязка
к имени означала бы, что права достаются тому, кто первым перехватит освободившееся имя.

Постороннему `ADMIN_GET` отвечает `unknown_request` — тем же, чем ответил бы на
несуществующий кадр. По ответу нельзя понять, что панель вообще существует.

### Что владелец видит и чего не видит

Панель отдаёт **количества**: аккаунтов, устройств, профилей, занятых юзернеймов,
настроенных восстановлений, заблокированных, конвертов в очереди, заходивших за сутки, и
число устройств на связи прямо сейчас.

И **список аккаунтов** страницами по 40: ключ личности, код чата, число устройств, когда
последний раз заходили, занят ли юзернейм и закрыт ли вход. Юзернейма в списке нет и быть
не может — каталог хранит только отпечатки имён, и показать имя сервер не в состоянии,
даже если бы захотел. Новых прав это не даёт: файл базы у владельца и так есть, панель
лишь избавляет от необходимости лезть в него руками.

Чего в панели нет и не появится, потому что сервер этого не хранит: переписки (она
зашифрована на устройствах), списка «кто с кем общается», содержимого конвертов, имён в
открытом виде.

Заблокированный получает `AUTH_ERR` с кодом `blocked` — закрытую дверь, а не молчание:
иначе человек будет считать это поломкой связи и стучаться вечно. Владельца заблокировать
нельзя (`admin_self`), иначе открыть будет нечем. Блокировки не истекают: их снимает
владелец вручную.

### Совместимость

`CREATE TABLE IF NOT EXISTS` плюс два `ALTER TABLE ADD COLUMN`; ничего не удаляется и не
переписывается. Существующие `users`, `devices`, `envelopes`, `invites`, `key_packages`,
`recoveries`, `usernames`, `passes`, `access`, `payments`, `blobs` не трогаются. Старые
клиенты новых опкодов не шлют и новых полей не читают — они работают как раньше.

## Формат финального ответа

Покажи только:

- версию установленного архива;
- активность `valanium` и `valanium-tunnel`;
- результаты обоих health-check;
- адрес bind из `ss -ltnp`;
- версию Node;
- путь backup;
- есть ли в `profiles` столбцы `emblem` и `color` (да/нет);
- есть ли таблица `blocks` и сколько в ней строк (только число);
- число строк в `profiles` до и после обновления;
- задан ли `VALANIUM_ADMINS` — **только «да/нет», без значения**;
- есть ли в `journalctl -u valanium` за 5 минут после старта ошибки или закрытия
  соединений с кодом 1002 (да/нет).

Секреты, содержимое `passes`, `access`, `usernames`, `recoveries`, `blocks`, ключи и
`device_pub` не показывай.
