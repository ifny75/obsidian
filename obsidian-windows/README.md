# obsidian-windows

Windows-клиент: WebView2 для интерфейса, [obsidian-core](../obsidian-core) для всего остального.

Ядро линкуется напрямую как обычная Rust-зависимость — FFI здесь не нужен, обе стороны на Rust. Словарь команд и событий при этом тот же, что пойдёт в Android через JNI, поэтому возможности добавляются в ядре, а не здесь.

## Запуск

```bash
npm install
npm run dev
```

Сборка установщиков (msi и nsis):

```bash
npm run build
```

Нужен WebView2 — на Windows 11 он предустановлен, для Windows 10 инсталлятор Tauri тянет bootstrapper сам.

## Как проверить переписку на одной машине

Поговорить с самим собой нельзя: MLS не добавляет в группу того, кто её создал. Значит нужны две копии с **разными базами** — путь задаётся переменной `OBSIDIAN_DB`:

```powershell
# первое окно
$env:OBSIDIAN_DB = "$env:TEMP\obsidian-a.db"; .\obsidian-windows.exe

# второе окно (новая консоль)
$env:OBSIDIAN_DB = "$env:TEMP\obsidian-b.db"; .\obsidian-windows.exe
```

Дальше: каждая копия открывает свою базу своим паролем, регистрируется своим инвайтом, копирует свой адрес устройства из шапки и вставляет чужой в поле «Адрес устройства собеседника».

Без переменной база лежит в `%APPDATA%\app.obsidian.messenger\obsidian.db`.

## Что где

```
src/                 интерфейс: три файла, без сборщика и фреймворка
  index.html         разметка трёх экранов
  styles.css         каркасные стили, переписываются целиком
  main.js            команды в ядро и отрисовка событий
src-tauri/
  src/main.rs        обвязка: открыть базу паролем, перекладывать JSON
  tauri.conf.json    окно, CSP, иконки
```

Сборщика нет намеренно: `frontendDist` указывает прямо на `src/`, поэтому правка вёрстки видна после перезагрузки окна, без node_modules во фронтенде и без шага компиляции.

## Мост между окном и ядром

Ровно три вызова, всё остальное — события:

```js
await invoke("unlock", { password });     // открыть локальную базу
await invoke("submit", { json });         // команда в ядро
await invoke("is_unlocked");              // база уже открыта?

listen("obsidian:event", ({ payload }) => { /* событие ядра, JSON */ });
```

`submit` принимает те же команды, что описаны в [obsidian-core/README.md](../obsidian-core/README.md): `status`, `conversations`, `connect`, `register`, `send`, `history`, `fingerprint`, `verify`, `disconnect`. Новая кнопка — это новая команда в ядре, а не новый Rust-код в `main.rs`.

## Если правишь интерфейс

- **Стили можно переписать целиком.** `main.js` обращается к элементам только по `id` и переключает классы состояний (`hidden`, `active`, `online` / `connecting` / `offline`, `in` / `out`, `visible`). Пока эти имена на месте, логика не сломается.
- **CSP строгая**: `script-src 'self'`, `style-src 'self'`. Инлайновые `<script>` и `style=""` не выполнятся — это не придирка сборщика, а защита окна. Внешние CDN тоже не загрузятся; шрифты и картинки класть в `src/`.
- **Криптографии в окне нет и не должно быть.** Оно получает уже расшифрованный текст и отдаёт открытый — граница доверия проходит по ядру.
- **Адрес устройства (64 hex-символа) — это то, что пользователь даёт собеседнику**, чтобы тот написал первым. Он же показан в шапке и копируется по клику.
- **Кнопка «Сверить»** показывает два кода, которые должны совпасть у обеих сторон. Подпись под ними говорит сверять их по другому каналу — это не занудство: показать код в той же переписке значит показать его тому, от кого защищаемся.
- **Баннер аномалии красный и не прячется сам.** Это единственное место в интерфейсе, где нельзя приглушать: `anomaly` означает возможную атаку, а не сбой.

## Чего пока нет

- Пароль базы не заворачивается в DPAPI — вводится при каждом запуске.
- Нет уведомлений, вложений, поиска по истории.
- Сверка есть, но окно не помнит, что вы её прошли: подтверждённого статуса контакта и предупреждения «код сменился» пока нет.
- Окно не помнит выбранный диалог между запусками.
