# obsidian-server

Релей для Obsidian. Принимает шифротексты, раздаёт их адресатам и ничего о них не знает.

Архитектура и модель угроз — в [../ARCHITECTURE.md](../ARCHITECTURE.md). Wire-протокол там же, §7.

## Запуск

```bash
npm ci --ignore-scripts
cp .env.example .env
npm start
```

Вход сейчас **только по инвайтам**. Платёжный шлюз на TON написан и покрыт тестами, но не
загружается: его пакеты лежат в `optionalDependencies`, а модули подтягиваются динамически
только при непустом `OBSIDIAN_TON_ADDRESS`. Совсем без них ставится так:

```bash
npm ci --ignore-scripts --omit=optional
```

Тесты разбора ячеек TON в этом случае помечаются пропущенными, остальные идут как обычно.

Требуется Node ≥ 24: используются встроенные `node:sqlite`, разбор TypeScript без сборки и `--env-file-if-exists`.

```bash
npm run check   # tsc, строгий режим
npm test        # юнит-тесты протокола
npm run smoke   # e2e: поднимает сервер и ходит по нему настоящим WebSocket
```

## Первый пользователь

Открытой регистрации нет. Код печатается один раз, в БД ложится только его SHA-256:

```bash
npm run invite
```

Клиент передаёт код в поле `invite` кадра AUTH. Других способов выписать инвайт нет: HTTP-путь для этого был и убран. Эндпоинт, заводящий доступ на сервер, торчал бы в интернет всегда, а нужен он раз в неделю с самой машины — там же, где и утилита.

## HTTP

Ровно два пути, оба без сессии, оба только на чтение. Всё остальное живёт в
сокете: каталог, KeyPackages и вложения по HTTP были вторым входом к тем же
данным, со своей проверкой прав и своим разбором тела.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/v1/health` | проверка живости: туннель и мониторинг смотрят её без входа |
| GET | `/v1/releases/latest` | версия и ссылки на сборки: клиент может быть старым и до сокета не дойти |

Bearer-токенов сервер не выдаёт: выдавать их было некому с тех пор, как
защищённые ими пути исчезли.

Опкоды `PAY_REQUEST` / `PAY_INFO` / `PAY_OK` остаются в протоколе, но при пустом
`OBSIDIAN_TON_ADDRESS` сервер отвечает на них ошибкой `payment_disabled`.

MLS KeyPackages ходят не по HTTP, а по сокету (`KEYPKG_PUBLISH` / `KEYPKG_CLAIM` / `KEYPKG`):
отдельный HTTP-путь означал бы в клиентском ядре второй TLS-клиент ради двух запросов.
HTTP-эндпоинты `/v1/keypackages` оставлены для отладки и инструментов.

CORS-заголовков нет намеренно: ходить сюда должен `obsidian-core`, а не браузер.

## Структура

```
src/
  index.ts          uWS: сокет, роуты, уборка по расписанию
  config.ts         всё настраиваемое, значения по умолчанию безопасны
  proto/frames.ts   опкоды, сборка и разбор кадров
  auth/             challenge-nonce, Ed25519, bearer-сессии
  ws/session.ts     машина состояний соединения
  db/               единственное место с SQL
  http/routes.ts    HTTP-эндпоинты
```

## Что важно знать, если правишь код

- **Буферы uWS невалидны после возврата из обработчика.** Всё, что переживает вызов, копируется сразу — иначе получишь тихую порчу данных под нагрузкой.
- **Конверт удаляется только по ACK клиента.** Backpressure и обрыв связи не теряют сообщение: оно доедет при следующем подключении.
- **Очередь отдаётся по `seq`, а не по времени.** Приглашение в MLS-группу обязано прийти раньше первого сообщения, а миллисекунды не различают кадры, отправленные подряд.
- **Ошибка разбора = разрыв соединения.** Ни одной попытки «дочитать как получится».
- **Логи без идентификаторов.** Ни pubkey, ни handle, ни IP, ни тел кадров — см. §13 архитектуры.
- Новое поле в БД, связывающее отправителя с получателем, — блокер, а не фича.
