# Obsidian

Приватный мессенджер: переписка шифруется на устройстве и хранится там же.
Серверу достаётся запечатанный конверт — открыть его нечем, ключей у него нет.

Клиенты для Windows и Android, общее ядро на Rust, релей на Node.

## Что внутри

| Каталог | Что это |
| --- | --- |
| `obsidian-core` | Ядро на Rust: MLS (RFC 9420) через OpenMLS, запечатанное хранилище, протокол. Общее для обоих клиентов. |
| `obsidian-windows` | Клиент для Windows: Tauri 2, ядро линкуется напрямую. |
| `obsidian-android` | Клиент для Android: Java поверх того же ядра через JNI. |
| `obsidian-server` | Релей: TypeScript на Node 24, `node:sqlite`, uWebSockets. |
| `deploy` | Systemd-юниты, конфиг nginx и инструкция для обновления сервера. |

## Как это защищено

- **Шифрование на устройстве.** Сообщения шифруются по MLS до отправки; ключи
  не покидают устройство. Смена состава беседы переводит группу в новую эпоху —
  прежние ключи к последующим сообщениям не подходят.
- **Личность — ключ, а не номер.** Ed25519 со строгой проверкой (`verify_strict`),
  устройство подписано ключом личности. Номер телефона не нужен.
- **Хранилище запечатано.** Каждая запись шифруется XChaCha20-Poly1305, ключ
  выводится Argon2id из пароля устройства и на диск не попадает.
- **Каталог имён хранит отпечатки.** Сервер не знает самих юзернеймов и не может
  выдать список пользователей по началу имени.

## Чего сервер не знает

Текста сообщений, вложений, состава групп и того, кто с кем переписывается:
связки «отправитель ↔ получатель» в его схеме нет. Ему видны запечатанный
конверт, адрес получателя в момент доставки и время — без этого письмо не
доставить.

Проверяется это не обещанием: сервер можно поднять свой, см. `deploy/README.md`.

## Сборка

```bash
# ядро и тесты
cd obsidian-core && cargo test

# клиент для Windows
cd obsidian-windows && npm install && npm run build

# клиент для Android (нужны Android SDK/NDK и cargo-ndk)
cd obsidian-android && ./gradlew :app:assembleDebug

# сервер
cd obsidian-server && npm ci && npm test
```
